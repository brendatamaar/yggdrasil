# Repo tracking — Model Functional Effect design

Covers WS-01: opt-in tracking of project folders through a folder browser, with preview and rescan. "Stop tracking" never touches files on disk. It also replaces the inline find-or-create logic in `ygg seed`.

Approved decisions (`docs/phases/phase-2.md`):

- untracking is soft (`untracked_at`); tracking the same path again restores the row and its build history;
- core lives in `internal/core/repos`, shell in `internal/repos`;
- state and audit are written in one `Store.Commit`; times and IDs come from the shell.

The aggregate is the **workspace**: every project and repo row, tracked or not. It is small (tens of projects, hundreds of repos), so one transaction loads all of it, decides, and writes the result. `BEGIN IMMEDIATE` serializes deciders, so there is no check-then-act race.

## State map

`repos.Workspace` (core, no JSON tags):

```go
type Workspace struct {
    Projects map[core.ProjectID]Project
    Busy     map[core.RepoID]BusyReason   // loaded by the shell: running build, running task (Phase 3)
}
type Project struct {
    ID      core.ProjectID
    Name    string
    Path    CleanPath          // canonical absolute folder (see Boundary)
    Life    Life               // sealed: Active{Since} | Untracked{At}
    Repos   map[core.RepoID]Repo
    Version int64
}
type Repo struct {
    ID      core.RepoID
    Name    string             // unique among the project's repos, tracked or not
    RelPath RelPath            // forward-slash path under Project.Path; "." for the folder itself
    Life    Life               // Active{Since} | Untracked{At}
    Trusted bool               // SF-09
}
type BusyReason string         // "build_running" | "task_running"
```

Per-row lifecycle (`Life`, sealed):

- `Active{Since}`: listed, visible to agents (SF-02), refreshed by repo-status.
- `Untracked{At}`: hidden everywhere, invisible to agents. Rows and build history stay.

"Missing folder" is not a tracking state. It is a health flag observed by repo-status, and tracking never acts on it automatically.

Preview and rescan results are **read models**, not stored state:

```go
type Preview struct {
    Path       CleanPath
    Candidates []Candidate   // found git repos under Path
    Truncated  bool          // the scan hit its limits
    Existing   *core.ProjectID // Path is already a project (active or untracked)
}
type Candidate struct {
    RelPath RelPath
    Name    string
    Known   *core.RepoID     // already a row in that project
    Active  bool             // that row is Active
}
type RescanReport struct {
    New     []Candidate      // found on disk, no row
    Missing []core.RepoID    // Active rows whose folder is gone or no longer a repo
}
```

## Inputs

All inputs carry `Now`. New IDs are pre-generated by the shell and passed in.

| Input | From | Fields |
|---|---|---|
| `TrackProject` | user: folder browser → preview → "Track"; `ygg seed` | `NewProjectID, Name, Path, Repos []Pick, Actor, Now` |
| `TrackRepos` | user: rescan → pick new repos | `ProjectID, Repos []Pick, Actor, Now` |
| `UntrackRepo` | user | `RepoID, Actor, Now` |
| `UntrackProject` | user | `ProjectID, Actor, Now` |
| `RenameProject` | user | `ProjectID, Name, Actor, Now` |

`Pick{RelPath, Name, NewRepoID}`: one selected candidate. The shell fills `NewRepoID` for every pick; the core uses it only when no row exists for that `RelPath`.

`Decide(ws Workspace, in Input) (Workspace, []Command, Outcome)` is the step. `Outcome` is the domain result returned to the caller:

- `Tracked{ProjectID, Added, Restored []RepoID}`
- `AlreadyTracked{ProjectID}`
- `NameTaken{Name}`
- `Overlaps{Other core.ProjectID}`
- `RepoBusy{RepoID, Reason}`
- `NotFound`
- `NothingPicked`
- `Untracked{IDs}`

## Transition table

"Project at Path" compares canonical paths (`CleanPath` equality, case-insensitive on Windows; this is decided by the boundary parser, not the core).

| From | Input | Guard | To | Commands |
|---|---|---|---|---|
| no project at Path | TrackProject | `len(Repos) ≥ 1`, Name free among Active projects, Path neither inside nor containing another Active project's Path | new Project Active, one Repo per pick (Active, `Trusted=false`) | `InsertProject`, `InsertRepo`×n, `WriteAudit(project.track)`, `WriteAudit(repo.track)`×n, `Publish(ReposChanged)`, `RefreshStatus(ids)` |
| Active project at Path | TrackProject | — | unchanged, but each pick is handled as in TrackRepos | same as TrackRepos; outcome `AlreadyTracked` when no pick changed anything |
| Untracked project at Path | TrackProject | Name free, no overlap | project Active again (`Name` updated), picks restored or added as in TrackRepos | `RestoreProject`, then as in TrackRepos, `WriteAudit(project.restore)` |
| Active project | TrackRepos | `len(Repos) ≥ 1` | for each pick: no row → new Active Repo; Untracked row → Active (`Trusted=false`); Active row → unchanged | `InsertRepo` / `RestoreRepo` per change, `WriteAudit(repo.track` or `repo.restore)` per change, `Publish`, `RefreshStatus(changed)` |
| Active project, Active repo | UntrackRepo | repo not in `Busy` | repo Untracked{Now} | `MarkRepoUntracked`, `WriteAudit(repo.untrack)`, `Publish` |
| Active project, Active repo | UntrackRepo | repo in `Busy` | unchanged | outcome `RepoBusy` |
| Active project | UntrackProject | no Active repo of it in `Busy` | project and all its Active repos Untracked{Now} | `MarkProjectUntracked`, `MarkRepoUntracked`×n, `WriteAudit(project.untrack)`, `Publish` |
| Active project | UntrackProject | some repo Busy | unchanged | outcome `RepoBusy` (first busy repo) |
| Active project | RenameProject | Name free among Active projects, non-empty | Name changed | `UpdateProject`, `WriteAudit(project.rename)`, `Publish` |

Rejections (no change, no commands, outcome only):

- `TrackProject` with no picks → `NothingPicked`;
- a taken name → `NameTaken`;
- overlapping paths → `Overlaps`;
- `TrackRepos`, `UntrackRepo`, `UntrackProject` or `RenameProject` on an unknown or Untracked project → `NotFound`;
- `UntrackRepo` on an Untracked repo → `Untracked{}` (idempotent, nothing written).

**Any other (state, input) pair: no change, no commands.**

A restored repo always comes back with `Trusted = false`: its agent config may have changed while it was untracked (SF-09). The trust prompt runs again before the next agent run.

Repo name collisions inside a project: a pick whose `Name` equals another row's name in the same project (tracked or not) gets `Name = RelPath`. `RelPath` is unique within a project, so the result is always unique. The core decides this; the user can rename later (not in Phase 2).

## Invariants

| # | Invariant | Property test |
|---|---|---|
| T1 | Active projects have pairwise distinct names, and no Active project's Path is equal to, inside, or containing another Active project's Path. | `TestPropActiveProjectsDisjoint` |
| T2 | Within a project, repo names are unique and `RelPath`s are unique, across tracked and untracked rows. | `TestPropRepoKeysUnique` |
| T3 | An Active repo belongs to an Active project. | `TestPropActiveRepoHasActiveProject` |
| T4 | No input ever removes a project or repo from the workspace (rows only change `Life`). | `TestPropNoRowRemoved` |
| T5 | A repo in `Busy` is never moved to Untracked. | `TestPropBusyRepoStaysTracked` |
| T6 | A repo that moves from Untracked to Active has `Trusted == false`. | `TestPropRestoreClearsTrust` |
| T7 | Tracking the same `(Path, picks)` twice gives the same workspace as once, and the second time emits no commands (idempotent). | `TestPropTrackIdempotent` |
| T8 | Every change of a row emits exactly one `WriteAudit` for that row; an input that changes nothing emits no commands. | `TestPropAuditPerRowChange` |
| T9 | Restoring keeps IDs: a re-tracked `(Project.Path, RelPath)` gets back its old `RepoID`, never the new one in the pick. | `TestPropRestoreKeepsID` |

## Commands

| Command | Cardinality | Idempotent | Produces |
|---|---|---|---|
| `InsertProject`, `InsertRepo`, `RestoreProject`, `RestoreRepo`, `MarkRepoUntracked`, `MarkProjectUntracked`, `UpdateProject` | one each | yes inside the one `Commit` (`UNIQUE` keys and the expected project versions reject a replay) | — |
| `WriteAudit{Action, Subject, Detail}` | one | committed with the rows | — |
| `Publish(ReposChanged)` | one, after commit | yes | — |
| `RefreshStatus{RepoIDs}` | one, after commit | yes (repo-status coalesces) | a `RefreshRequested` input to repo-status |

There are no external calls. The scan for preview and rescan is a read-only effect done before `Decide`. It is not a command.

## Call graph

```go
// Production
GET  /api/fs/dirs?path=                       // folder browser
  → repos.ParseBrowsePath (boundary) → CleanPath | "" for roots
  → platform.ListRoots() (drives on Windows, "/" elsewhere)  |  fs.ListDirs(path)
      → os.ReadDir; skip reparse points (platform.IsReparsePoint); flag IsRepo (.git dir or file)
  → api DTO

POST /api/projects/preview {path}
  → repos.ParseFolder (boundary: Abs, platform.CheckPath, LongPath canonical form, must exist and be a dir)
  → repos.Scan(path, limits)                  // read-only walk, see Boundary
  → store.LoadWorkspace (read)                // to fill Existing / Known / Active
  → repos.BuildPreview(scan, ws) [core]       // pure
  → 200 Preview DTO

POST /api/projects {path, name, picks[]}      |  ygg seed <folder> [name]
  → ParseFolder + ParsePicks (RelPath under path, unique, ≤ 200)
  → TrackingService.Track(ctx, input)          // api-side interface (internal/api/doc.go)
      → ids.New("prj") / ids.New("rep")×n, now := clock.Now()
      → Store.Commit(func(tx) {
            ws, busy ← tx.LoadWorkspace() + busy builds (tx.ListActiveBuildRepos)
            ws2, cmds, outcome ← repos.Decide(ws, input)        [core]
            apply row commands via tx (InsertProject, …, version-checked)
            tx.AppendAudit(audit.Prepare(…)) per WriteAudit
        })
      → after commit: hub.publishNext(ReposTopic{}, …); status.Refresh(ids)
  → outcome → 201 / 200 AlreadyTracked / 409 NameTaken|Overlaps|RepoBusy / 404 / 400 NothingPicked

POST /api/projects/{id}/rescan
  → store.GetProject → Scan(project.Path) → repos.Rescan(scan, ws, id) [core] → RescanReport

POST /api/projects/{id}/repos {picks}   → Track (TrackRepos)
DELETE-free API: POST /api/repos/{id}/untrack, POST /api/projects/{id}/untrack, PATCH /api/projects/{id} {name}
```

```go
// Tests
repos.Run(ws, inputs) (core only)         → T1–T9
TrackingService tests → SQLite in t.TempDir (store contract) + fstest/tmp dirs for Scan
Scan tests            → t.TempDir trees: nested repos, .git files (worktree), junctions (Windows), node_modules, limits
```

## Failures

| Node | Failure | Class | Handling |
|---|---|---|---|
| ParseFolder | relative, WSL, device path, missing, not a dir, empty | domain outcome | 400 with what to do ("choose a folder on this machine") |
| Scan | permission denied on a subfolder | escape hatch | skipped, counted in `Preview.Skipped`; the scan continues |
| Scan | limit hit (dirs visited, repos found, depth) | escape hatch | `Truncated = true`; UI says "showing the first N" |
| Scan | reparse point (junction, symlink) | escape hatch | not followed (no loops, no escape from the folder) |
| Decide | NameTaken / Overlaps / RepoBusy / NotFound / NothingPicked | domain outcome | 409 / 404 / 400 with a plain message |
| Commit | `db.ErrConflict` (version or UNIQUE) | retry | reload and decide once more; a second conflict → die (logged, 503) |
| Commit | busy / IO | die for this request | 503 "try again"; nothing written |
| after-commit publish/refresh | — | escape hatch | best effort; the UI refetches on reconnect, and repo-status Tick catches up |

Error translation: `os` errors → scan skip counts; `db` sentinels → `apperr` classes (Conflict/NotFound) → HTTP.

## Persistence and delivery

- **Migration 00003:**
  - `projects.untracked_at TEXT`, `projects.version INTEGER NOT NULL DEFAULT 0`;
  - `repos.untracked_at TEXT`, `repos.rel_path TEXT NOT NULL DEFAULT '.'`;
  - replace `projects.name UNIQUE` with a partial unique index on `name WHERE untracked_at IS NULL`;
  - keep `UNIQUE (project_id, name)` on repos, and add `UNIQUE (project_id, rel_path)`.
  - Existing rows are migrated: `rel_path` is derived from `repos.path` relative to `projects.path` (or `.`).
- **Paths:** `repos.path` stays the absolute canonical path (derived: `Project.Path` + `RelPath`). It is kept for queries and for the agent scope check.
- **Version check:** the project row carries the version, and every row change in a decision bumps it. Two decisions racing on one project → one gets `ErrConflict` and re-decides.
- **Visibility (SF-02):**
  - every store read used by the API lists, task creation and (later) agents/MCP filters `untracked_at IS NULL`;
  - task creation refuses an untracked repo (`NotFound`);
  - an archtest or a store contract clause pins the filter.
- **Effects:** none inside the transaction other than row writes and audit rows. Publish and refresh happen after commit.
- **No timers, no inbox:** every input is a user action, and duplicates are absorbed by T7.
- **Shell invariants (chaos):**
  - S1: a crash at any point leaves either the whole decision or none of it (one transaction);
  - S2: no file or folder under a tracked or untracked path is ever created, changed or removed by tracking (checked by hashing a temp tree before and after a track/untrack/rescan run).

## Boundary

| Source | Parser | Produces | Rejects |
|---|---|---|---|
| folder path from HTTP or CLI | `repos.ParseFolder(raw)` | `CleanPath` (absolute, `filepath.Clean`, canonical case for the drive letter, long-path prefix stripped for storage, `platform.CheckPath` passed) | empty, relative, WSL/device path, NUL, not existing, not a directory |
| browse path | `repos.ParseBrowsePath(raw)` | `CleanPath` or roots | same as ParseFolder, except "" means roots |
| picks | `repos.ParsePicks(raw, path)` | `[]Pick` | empty, duplicate RelPath, `..` segments, absolute RelPath, more than 200, name empty or over 100 runes or containing control characters |
| project name | `repos.ParseName(raw)` | `string` (trimmed) | empty, over 100 runes, control characters |
| DB rows | `db.workspaceFromRows` | `repos.Workspace` | unknown life combination (untracked repo without its timestamp, Active repo in an Untracked project), duplicate RelPath |
| scan of disk | `repos.Scan` (an effect, not a parser) | `ScanResult{Repos []RelPath, Truncated, Skipped}` | — |

Each parser row gets:

- round-trip (`ParseFolder(Format(p)) == p`, and the same for RelPath and Name);
- accepted ⇒ valid;
- one test per rejection rule;
- a fuzz target: `FuzzParseFolder`, `FuzzParsePicks`, `FuzzParseName`, `FuzzWorkspaceFromRows`.

`CleanPath` equality is defined by the parser's canonical form, so "same path" in the core is plain `==`.

## Open questions

Each question has a recommendation; the design above assumes it.

1. **Scan depth and skips:** the default depth is 3 below the project folder. The scan skips `node_modules` and hidden folders and stops at a repo root. Limits: 5,000 folders visited, 200 repos. *Recommend as stated.*
2. **A repo folder that disappears:** shown as a "Missing" problem by repo-status and offered as "stop tracking" in rescan, but never untracked automatically. *Recommend as stated.*
3. **Renaming repos:** not in Phase 2. Names default to the folder name, or to `RelPath` on a collision. *Recommend deferring.*
